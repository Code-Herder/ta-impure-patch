WHAT IT SAYS
  1. NO MODEL FAILED TO RECONSTRUCT. norecon = 0 in every window over 82 unit
     types: `pose_accum_body` came back with a whole piece tree every time.
  2. NO DISAGREEMENT WITHOUT THE ENGINE'S OWN FLAG. Not one of the 27142 lines
     read dirty=0/0 — the signature `recon_watch` exists to catch ("a large err
     with the flag clear both times" = the guard's bracket is not the whole
     window). Every err over 4 model units is a buffer the engine was itself
     saying was stale or mid-rewrite.
  3. THE EXTREMES ARE EXACT. The bigmodels stop — ARMSCORP, CORSCORP, CORGANT,
     CORKROG, ARMVULC, CORDOOM, ARMBRTHA, ARMANNI — read errmax 0.00 with zero
     guard trips and zero rest-equal reads across both windows. The 36-piece
     tree and the 304-face model reconstruct to the printed 0.00.
  4. Walking units read 10-19; aircraft 24-35 with rest=0 (their buffers are
     actively composed, and the guard catches the rewrite). Both are the tick
     lag and the mid-rewrite window §2.9 already describes, not a bad rebuild.

THE ONE THING THIS FOUND THAT WAS NOT THE QUESTION
  A handful of STRUCTURES sit byte-equal to their own rest vertex arrays
  permanently — `rest=` runs at tens of piece-reads per frame on the ground and
  structure stops while `guard=` names only three to six units — with the pose
  flag set on both sides of every read. Their err is therefore the model's own
  size (39-62) for the whole session, and `posefix` draws them from the
  reconstruction every frame rather than occasionally. Identified by peeking
  Object3do+0x0C -> unit+0x92 -> the def's name on the run of the same fixture:
  "Gaat Gun", "Sentinel", "Solar Collector" (both sides), "Vulcan",
  "Scorpion", "Wind Generator", and one aircraft, "Hurricane".
  WHY the engine leaves those buffers at rest is NOT established here. It does
  not affect Gate A — the rest-equality detector catches every one of them and
  the reconstruction is what gets drawn — and G16 stops reading that buffer at
  all, so it becomes moot rather than fixed.

REPRODUCING IT
  tools/tacli arm <i> 'native.on=all wrecks' terr.on feat.on posewatch.on
  tools/tacli scenario load <i> pose-inventory --restart --res 1024x768
  tools/tacli eye <i> 1716 806     # ground     (cluster centre 2100,1200)
  tools/tacli eye <i> 2716 806     # structures (3100,1200)
  tools/tacli eye <i> 3616 806     # bigmodels  (4000,1200)
  tools/tacli eye <i> 2216 1606    # air        (2600,2000)
  grep -a 'native: ' <gamedir>/tagpu.log   # guard= rest= norecon= errmax=
  grep -a 'posewatch: .* dirty=' <gamedir>/tagpu.log | grep -c 'dirty=0/0'  # must be 0

  The posewatch filmstrip writes ~250 kB/s of tagpu.log at this unit count
  (one fopen/fclose per line), so a stop is measured in a slice of the file by
  byte offset, not by grepping the whole of it.
